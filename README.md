# 缤纷颜色 AI 游戏人设改写代理（ai-game-prompt-proxy）
界面截图：
<img width="995" height="1170" alt="ai-game-prompt-proxy" src="https://github.com/user-attachments/assets/75c3c0b8-79fc-4efc-a6fe-05ce70b30c14" />


一个轻量级、单文件的本地 HTTP 代理工具：拦截游戏发往大模型的 OpenAI 兼容请求，按你设定的规则**替换 system 报文里的人设区间**，再把报文转发给本地 Ollama 或外援 API。自带网页管理面板（WebUI），无需写代码即可配置规则、切换上游、管理局域网设备。

> 本项目为个人免费开源小工具，仅供个人非商业使用。

## 工作原理

```
游戏 / 客户端
   │  POST /v1/chat/completions（OpenAI 兼容报文）
   ▼
proxy_webui.py（本地代理，默认 127.0.0.1:4000）
   │  按规则在 system 报文里定位「起始标记…结束标记」区间，替换为人设正文
   ▼
本地 Ollama（11434） 或 外援 API（DeepSeek 等 OpenAI 兼容接口）
   │  模型回复按原格式（流式 / 非流式）原样回传给游戏
```

- 代理只做**定位 + 替换 + 转发**，流式与非流式响应都原样透传，不改变对话格式。
- 规则匹配不到、或必含关键词不全时，**原文原样透传，不插入、不改动**，避免产生重复的内容副本。

## 环境依赖与安装

只需要两个第三方库：

```bash
python -m pip install -r requirements.txt
# 或
pip install flask requests
```

**已知前提**：使用本地模型时，需预先部署并正常运行 Ollama 服务，并提前拉取好对应模型；使用外援 API 则准备好 OpenAI 兼容接口的 `api_base`、`api_key`、`api_model`。

## 快速开始
   安装运行环境：
   | Python | 3.13 |
   安装第三方库：
   pip install flask requests
1. 把 `proxy_webui.py`（及 `requirements.txt`）放在一个独立文件夹。
2. 启动：
   下载全部文档，并且放在同一文件夹下
   运行：
   自启动.bat

3. 启动后会自动打开 Web 管理页面（默认 `http://127.0.0.1:4000/`）。控制台会同时打印：
   - 规则编辑网页：`http://127.0.0.1:4000/`
   - 游戏 API 地址：`http://127.0.0.1:4000/v1`
4. 在游戏 / 客户端的 OpenAI 兼容设置里，把接口地址（base_url）由原来的 游戏/软件内接口地址改为代理地址 `http://127.0.0.1:4000/v1`，模型名按你的规则填写，即可开始走代理。

> 端口被占用时，见 [命令行参数](#命令行参数) 或在 WebUI「修改服务地址 / 端口」里更换后重启。

## WebUI 功能使用

### 1. 全局人设改写配置（config.ini）

页面第一块「人设改写配置」点 **保存配置** 后写入 `binfenconfig/config.ini`，是本机始终生效的那一条基础配置 + 上游 + 监听设置。

字段说明：

| 字段 | 含义 |
| ---- | ---- |
| 规则名称 | 便于识别，如「道侣-阿绫」 |
| 匹配方式 | 按 model 字段命中 / 消息关键词命中（见下节） |
| 匹配值 | 模型名，或关键词 / 正则 |
| 匹配范围 | 仅关键词模式生效：全部消息 / 仅 system / 仅 user |
| 使用正则 | 关键词是否按正则表达式匹配 |
| 启用 | 启用 / 停用本条 |
| 区间起始标记 / 区间结束标记 | 圈定要替换的文本范围（默认 `## 守住世界观` … `## 角色属性`） |
| 替换方式 | 保留起止标记只换中间 / 连起止标记整段替换 |
| 区间内必含关键词 | AND 条件，见 [第 4 节](#4-区间内必含关键词and) |
| 替换进去的人设文本 | 区间被替换成的正文 |

### 2. 匹配方式

- **按 model 字段命中**：请求报文里的 `model` 等于匹配值即命中。最常用——用不同模型名区分不同角色 / 场景，各自套不同人设。
- **消息关键词命中**：已废弃。

### 3. 替换区间与替换方式

- 程序在报文里从「起始标记」找到「结束标记」（取两者最近一对），圈出这一段。
- **保留起止标记（只换中间）**：两句标记本身保留，只把它们之间的内容换成人设正文。
- **连起止标记整段替换**：从起始标记第一个字到结束标记最后一个字（含这两句标记）整体换成人设正文，适合把旧角色设定 / 背景整段抹掉重写。

### 4. 区间内必含关键词（AND）

填写一组关键词（逗号 / 顿号 / 分号分隔，符号必须为英文标点），**必须全部出现在起始…结束区间内**才执行替换；缺任意一个则本条不生效、原文透传。留空表示不校验。

用途：同一个区间标记可能在多个角色报文里出现，靠"区间内必须包含某角色名"锁定只替换该角色，避免误替换到别人。

### 5. 多规则列表（rules.json）

点 **保存规则（添加/更新）** 把当前表单作为一条规则加入 / 更新到下方「现有规则」列表，存入 `rules.json`。可添加多条，逐条启用 / 停用 / 编辑（回填） / 删除。每条规则的字段与全局配置一致。

执行顺序：先跑全局单条配置，再依次遍历 rules.json 里的规则；每条独立判断、独立替换。

### 6. 外援 API 切换

「外援 API」区块填好 **接口地址 api_base + 密钥 api_key** 即走外援（自动带 `Bearer` 鉴权，并用外援模型名 `api_model` 覆盖请求模型）；两项都留空则回退本地 Ollama。非Ollama本地模型可遵循外援模型设置方式，此区块随「保存配置」写入 config.ini。

示例：

```
api_base: https://api.deepseek.com/v1
api_key:  sk-xxxxxxxx
api_model: deepseek-chat
```

### 7. 控制台输出模式

即时切换、自动记住、无需重启，写入 config.ini：

- **详细调试**：打印改写前后完整报文 + 模型回复，便于排查。
- **精简**：只输出每轮一行汇总（规则条数 / 成功替换次数 / 命中规则）+ 连接错误。

### 8. ini 导出 / 导入 / 批量导入

| 按钮 | 作用 | 存储位置 |
| ---- | ---- | ---- |
| 导出为 ini | 把当前界面配置存为一个 ini | `binfentext/<规则名>.ini` |
| 导入 ini（覆盖当前配置） | 选一个 ini，解析后**覆盖全局 config.ini** | 写 `binfenconfig/config.ini` |
| 批量导入规则 INI（多选） | 多选 ini，按名称**批量合并进规则列表 rules.json**；同名跳过、缺人设文本判无效 | 写 `rules.json` |

注意区分：「导入 ini」覆盖的是全局单条配置；「批量导入规则」进入的是多规则列表。

### 9. 局域网设备管理（IP / 网段独立上游）--测试性功能

用于一台代理服务供局域网多台设备 / 多个角色共用，每台设备可有自己的上游与专属规则。

- **本机 127.0.0.1 永远豁免**，走全局 config.ini + rules.json，不受设备表限制。
- **外部 IP**：在设备表中按精确 IP 或 CIDR 网段登记；**未登记或已停用的 IP 直接返回 403 拒绝**。
- **IP / 网段**：填单台精确地址（如 `192.168.1.20`），或填 CIDR 网段（如 `192.168.1.0/24`）批量放行整段。
- **上游模式**：本地 Ollama / 外援 API（按模式为准，local 即使误填密钥也不转外援）。
- **专属规则**：每台设备可挂自己的规则集合，与全局规则互不干扰。
- **在线状态**：被动探测，3 分钟内有请求显示「在线」，否则「离线 / 最近 x 分钟」；状态在内存中，重启程序后清空。

设备配置独立保存在 `binfenNetwork/network.ini`（多段 `[device:名称]`）。建议在路由器给设备绑定固定 IP，避免 DHCP 变动后失效。

## 文件与目录说明

| 路径 | 内容 |
| ---- | ---- |
| `proxy_webui.py` | 主程序（单文件） |
| `binfenconfig/config.ini` | 全局生效配置：单条规则、外援、监听地址 / 端口、控制台模式 |
| `rules.json` | 多规则列表（保存规则 添加/更新） |
| `binfentext/` | 导出的 ini 规则文件 |
| `binfenNetwork/network.ini` | 局域网设备表（IP/网段、上游、专属规则） |
| `自启动.bat` | 启动程序 |

首次启动会自动创建缺失的目录与默认文件。旧版 `devices.json` 仅作首次迁移回退，新配置一律写 network.ini。

## 命令行参数

命令行参数优先于配置文件：

```bash
python proxy_webui.py [监听地址] [监听端口]
```

示例：

```bash
python proxy_webui.py 127.0.0.1 4001
```

- 监听地址默认 `127.0.0.1`（仅本机）；局域网共用填 `0.0.0.0`（浏览器仍用 127.0.0.1 打开面板）。
- 端口默认 `4000`，被占用就换 `4001` 等。

## 常见问题排查

- **游戏连不上 / 502 无法连接上游**：本地模式先确认 Ollama 已启动且在 11434；外援模式确认 api_base / api_key / api_model 填写正确、网络可达。
- **替换没生效**：切到「详细调试」看改写前报文，确认起始 / 结束标记在报文里确实存在、拼写完全一致；检查必含关键词是否全部出现；确认规则处于启用状态。
- **端口占用**：控制台报端口冲突时，换端口重启，或在 WebUI 改端口后重启。
- **改了端口网页打不开**：端口修改需重启程序生效；命令行参数即时优先。
- **外部设备被 403**：把该设备 IP / 网段登记进设备表并启用。

## 安全与隐私注意事项

- 代理只把报文转发到你指定的上游（本地 Ollama 或你自己填写的外援 API），不向其他地方上传对话内容。
- `api_key` 保存在本地 ini 文件里，**不要把含密钥的 config.ini / network.ini 提交到公开仓库或发给他人**；公开发布前请检查并移除密钥（可配合 `.gitignore`）。
- 监听 `0.0.0.0` 开放局域网时，未登记 IP 会被 403，但仍建议仅在可信内网使用。
